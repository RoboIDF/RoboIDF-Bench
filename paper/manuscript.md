**English title:** RoboIDF-Bench: A Layered Evaluation Protocol for Agentic Robot System Identification

版本：v0.1，研究协议完整初稿；日期：2026-11-01。作者、机构与投稿渠道待确定，本文不填写未经确认的署名。

> **证据状态：** 本文提出评测设计，不是已完成实验的结果论文。截至本稿日期，本仓库仅有规划文档、维护约定和 Pixi 基础环境；尚无评测实现、发布数据集或实测成绩。以下 Schema 字段、级别验收细则和统计方案均为待评审提案，不构成已发布的跨仓库接口。实验表中的“待测”不代表零值。MuJoCo SysID 等外部能力的存在不代表本项目已安装、集成或验证它们。

## 摘要

机器人系统辨识的工程结果同时依赖实验激励、传感时间语义、动力学参数化、优化后端及模型转换。Agent 可以协助组织这些环节，但生成模型文件、完成工具调用或给出自信的结论，均不足以证明辨识成功。本文提出 RoboIDF-Bench，一套与 Agent 自评相分离的评测协议，以可辨识真值恢复、独立轨迹预测、预算约束下的实验效率和模型兼容性四类证据检验完整工作流。协议划分 Synthetic、Offline Real Robot、Agentic SysID 和 Model & Compatibility 四个套件，规定任务与数据合同、物理单位、归一化尺度、训练开发测试隔离、相同后端对照、预算耗尽与终止事件的统计处理，以及独立复现要求。安全违规、人工干预和失败不被压缩进单一总分，而作为必须同时呈现的结果维度。本文同时给出可预注册的实验设计与空白报告表，并讨论硬件异质性、不可辨识性及闭源服务漂移对结论的限制。本文的贡献是可审阅的协议设计；其可执行性、区分能力和跨设备推广能力仍须通过后续实现与实验验证。

**关键词：** 机器人系统辨识；Agent 评测；主动实验；可辨识性；可复现性；跨仿真器验证

## 1 引言

机器人模型校准不是单一优化问题。即使优化器能够降低拟合残差，错误的反馈语义、未记录的控制器增益、时钟偏差或仅覆盖局部工况的训练轨迹，仍可能产生无法推广的模型。另一方面，真实系统中多个参数可能以组合形式影响观测，预测准确并不自动意味着质量、惯量、摩擦和时延均已被单独恢复。对于带位置内环的设备，外部辨识结果尤其可能只是特定控制模式下的等效模型。

Agent 引入了新的评测对象：它可以选择实验、调用后端、诊断失败并组织模型发布。传统只比较最终残差的表格难以回答这种组织能力是否节约实验资源，是否只是使用了更多计算或人工提示，以及是否在困难任务上选择性退出。RoboIDF-Bench 因此把评测单位从一次优化扩展为“从固定初始条件到独立验收的完整运行”。

本文围绕四个研究问题组织协议。RQ1：在可辨识条件下，方法能否恢复正确参数，并在不可辨识或结构失配时承认证据不足？RQ2：模型能否预测独立真实轨迹，且收益不是由测试集泄漏或时间对齐作弊产生？RQ3：在相同后端与资源约束下，Agent 的实验组织是否改善成功率、成本或恢复能力？RQ4：模型及适配器是否可独立加载、跨引擎复现，并被外部贡献者在不修改 Core 的条件下接入？

拟议贡献包括：四套件证据结构；区分参数真值与预测效用的指标合同；同时处理失败、成本及安全的报告协议；与既有社区级别配套的证据检查和独立复现标志。我们不主张该设计已经优于现有基准，也不声称已建立覆盖所有机器人类型的公共数据集。

## 2 相关工作与定位

YCB 工作将公共对象模型与实验协议共同作为可比较机器人研究的基础，说明共享资产之外还需要明确过程和量化方法 [@ycb2015]。RoboIDF-Bench 借鉴这一原则，但评测目标是系统辨识与工作流，而非抓取任务本身。

MuJoCo 的官方 System Identification Toolbox 文档描述了用记录传感数据拟合仿真参数的流程，包括有界非线性最小二乘、参数化和残差处理 [@mujoco_sysid]。Isaac Sim 的官方 System Identification Extension 文档同样描述了命令回放、遥测比较和参数调整 [@isaac_sysid]。这类工具是拟议后端候选；本文不把“接入后端”作为重新发明优化器，也不把文档能力当作本项目能力。具体版本及依赖兼容性须在实际实验时冻结。

Agarwal 等对有限重复次数下的评估提出区间估计和性能分布报告，指出只使用聚合点估计的风险 [@agarwal2021]。本文将这一统计审慎原则用于机器人辨识，但硬件运行存在会话相关、磨损和信息性终止，不能机械地把仿真随机种子当作独立机器人样本。

这些来源支撑本文的问题设定与方法选择，不构成对整个领域的穷尽综述。主动辨识、参数可辨识性和跨引擎验证仍需补充更系统的原始文献检索后再形成投稿版定位。本文不提出未经检索证明的“首个”或“唯一”主张。

## 3 问题定义与证据合同

令机器人在控制模式 c 下满足 x(t+1)=f(x(t),u(t);$\theta$,c)+w(t)，观测为 y(t)=g(x(t);$\phi$)+v(t)。$\theta$ 表示动力学与执行器参数，$\phi$ 表示测量增益、偏置及传感链属性。设备时间与主机时间通过记录的映射关联。命令到机械响应的物理时延与时间戳对齐偏差分别建模；不能以任意移动测试轨迹来掩盖错误动力学。

一个任务实例由机器人与装配描述、初始模型、参数声明、允许动作集合、数据访问范围、预算、独立评估器和验收规则共同确定。每个参数带物理含义、单位、坐标约定、边界、先验来源及状态。状态沿用项目群的 `IDENTIFIED`、`EFFECTIVE_ONLY`、`UNIDENTIFIABLE`、`PRIOR_ONLY`；只有存在可辨识证据且含义匹配的参数进入真值恢复指标。状态判据本身须记录，不能由 Agent 任意给出标签后免于验收。

拟议任务清单至少包含以下字段组：

| 字段组 | 必需信息 | 评测用途 |
|---|---|---|
| 身份与版本 | task_id、suite、协议版本、任务资产哈希、Core 合同版本 | 保证比较对象一致 |
| 机器人与装配 | 组件标识、关节映射、单位、坐标系、装配变换及其来源 | 防止结构或坐标错误被当作辨识误差 |
| 控制与测量 | 控制模式、命令与反馈语义、采样周期、时钟域、校准版本 | 确定可观测目标与对齐规则 |
| 模型与后端 | 初始模型哈希、参数状态与边界、后端版本、求解配置 | 隔离初始化及优化器差异 |
| 访问与预算 | 数据权限、实验次数、物理执行时长、计算与人工预算 | 约束完整运行 |
| 验收与审计 | 指标、阈值、失败分类、停止条件、运行日志及产物哈希 | 独立判断结果与追溯 |

数据合同要求逐段记录命令、反馈、设备和主机时间戳、丢包与饱和标志、重置事件、温度或载荷等已测工况。未采集的通道明确记为缺失，不能填入看似合理的数值。原始数据不可覆盖；重采样、滤波、导数估计和对齐产生单独版本及参数记录。标注派生速度时说明其由位置差分还是设备传感得到，并把处理延迟纳入分析。

Core 维护通用合同，Bench 只提出评测所需约束并消费版本化产物。本文表格为研究草案，后续经跨项目评审才可转为机器可检查的 Schema；不在本文阶段复制或悄然改变 Core 接口。

## 4 四类评测套件

### 4.1 Suite A：Synthetic

合成套件提供已知生成机制和真值，以逐步增加难度的任务识别评测器与方法的行为。拟从单关节低阶系统出发，扩展至耦合机构、非线性摩擦、执行器饱和、噪声、时延及接触。每一类扰动单独控制，再设计联合扰动；训练与测试激励覆盖范围应显式记录。生成器版本、真值和随机种子由评估侧保存。

A 设可辨识、弱可辨识与结构失配三个子组。前者比较参数恢复与预测；后两者主要比较不确定性、失配诊断和预测适用域。对于只能恢复参数组合的任务，使用预定义组合映射 h($\theta$) 比较，不能对每个原始参数宣称恢复。识别能力应通过激励覆盖、灵敏度或预先选定的秩诊断说明，不能只凭优化器收敛判断。诊断误报与漏报以任务级混淆矩阵呈现。

### 4.2 Suite B：Offline Real Robot

离线套件向各方法提供完全一致的真实训练数据和初始模型，隔离主动采样的影响。拟以 Tianji 与 Wuji Hand 2 相关数据作为未来候选，但目前设备配置、手数量、固件、关节映射、安装变换、数据授权与可发布范围均待核验，本文不将其列为已可用数据集。

按采集会话与轨迹族分组切分数据，并保留工况变化的分布外测试。评价包括位置、速度、时延、频率响应及长期开环回放。若反馈只揭示闭环行为，则结论限定为该控制模式下的等效预测。真实硬件通常没有精确动力学真值，因此不能以工程标称值作为无误差金标准。校准仪器或独立测量若可用，应同时记录其不确定性。

### 4.3 Suite C：Agentic SysID

Agentic 套件要求所有方法从相同初始模型、可用传感通道、允许实验空间及资源预算出发。Agent 可提出实验并接收训练或开发反馈，独立评估侧在运行结束后验收冻结产物。高层实验工具先进行权限与约束检查，物理执行由独立安全监督控制；模型文本中的“安全”声明不替代执行层保护。

C 同时测量辨识误差、开发阶段达标成本、最终独立成功率、人工介入、故障恢复与安全事件。恢复任务采用预注册的故障注入，例如可重试通信中断或缺失观测；只在模拟或获准测试条件下开展，不为制造统计样本而触发危险硬件行为。恢复率以遭遇指定且可恢复故障的运行数为分母，不能把所有无故障运行算作恢复成功。

### 4.4 Suite D：Model & Compatibility

D 将结构正确、可加载和动态一致性分开验收。结构层检查组件装配、关节映射、坐标系、单位和依赖声明；接口层检查 Adapter 合同、是否必须修改 Core、错误返回及停止语义；资产层在洁净环境独立加载模型；动力学层在相同输入、初始条件、控制语义和明确仿真设置下回放。

Cross-Simulator 属于 D，复用 B 的动态误差定义。比较必须记录积分步长、求解器、接触参数、执行器映射和转换损失。两个引擎相互接近不能证明它们都接近真实系统，故分别报告引擎间差异和各引擎对真实保留数据的误差。无法等价映射的特性逐项列出，不以导出 MJCF/USD 成功代替动态验收。

## 5 指标、单位与聚合

对轨迹 r、通道 j 的有效观测索引集合 V(r,j)，定义

`RMSE(r,j) = sqrt(sum_{t in V(r,j)} (y_hat(r,t,j)-y(r,t,j))^2 / |V(r,j)|)`。

转动关节位置采用 rad、角速度采用 rad/s，移动关节分别采用 m 和 m/s；转矩为 N·m，力为 N，时延为 s，执行与等待时间为 s。周期角度是否取最短角差须由关节类型预先规定，不能对有圈数意义的关节随意折返。缺失样本不计入有效项，但覆盖率 `|V|/N_expected` 必须同时报告；覆盖率低于预设门槛的轨迹不能靠删除难点获得好成绩。

无量纲误差定义为 `NRMSE(r,j)=RMSE(r,j)/s_j`。尺度 s_j 在训练数据或独立工程规格上冻结，推荐使用任务声明的参考运动幅度；若用训练标准差，则说明估计方法。s_j 必须正且与测试输出无关；近常量通道使用预注册工程尺度或报告 N/A，禁止按测试误差临时选分母。不同量纲先分别报告，再在同类通道内宏平均；不同机器人采用任务级等权汇总，同时保留单任务分布，避免长轨迹或高自由度设备支配结果。

可辨识参数集合 I 的归一化误差为 `E_theta = sqrt((1/|I|) sum_{k in I} ((theta_hat_k-theta_star_k)/a_k)^2)`，a_k 是预注册的物理参考尺度或允许区间宽度。若真值为零也不产生除零；不默认用真值绝对值作分母。报告每参数原始单位误差和集合 I，不能通过事后缩小 I 改善成绩。等效参数只接受与其声明目标一致的预测验证。

时延误差在 A 或有独立校准参照时为 `E_delay=|d_hat-d_ref|`，单位 s；没有可靠参照时只报告估计值及不确定性。频率响应在预先定义的激励频带 F 上分别报告幅值误差（dB）与相位误差（rad），其中 `E_mag=sqrt(mean_f [20 log10(|H_hat(f)|/|H_ref(f)|)]^2)`；低于预设噪声底或相干性门槛的频点不纳入并报告覆盖率，相位差的展开规则固定。长期回放误差为随预测时域 H 变化的 `E_roll(H)`，每个 H 使用统一初始状态和相同积分规则，不在每一步重新注入真实状态。

验收使用预注册的多条件门槛：数据有效、必要预测指标达标、预算合规且没有禁止级安全事件。阈值必须来自任务要求、仪器精度或事先规定的工程容差，并在查看最终测试成绩前固定。当前没有可支持的数值阈值，因此本文不填造具体门槛。可另列误差与成本的 Pareto 前沿，但安全、人工成本、覆盖率和失败类别始终独立展示，禁止通过任意加权总分抵消严重安全事件。

## 6 预算、失败与删失统计

资源预算是向量 `B=(N_exp,T_robot,T_wall,C_compute,N_tool,C_human)`，分别表示启动实验次数、物理运行时间、总墙钟时间、计算配额、工具调用及人工成本。计算配额需固定硬件或采用明确可计费单位；LLM token、请求次数、CPU/GPU 时间分别记录，不伪装成完全可互换的成本。失败实验、预检查拒绝、重试和恢复的计费规则提前声明；预检查拒绝不算物理执行，但算尝试与工具成本。缓存、离线调参与方法研发预算单列。

运行状态至少区分成功、预算耗尽、数值失败、数据无效、基础设施失败、用户撤回和安全终止。成功率以预注册启动运行数为分母，全部状态进入主表。基础设施失败可按事先规则补跑，但原记录和包含原失败的敏感性分析仍保留。只报告成功运行的平均误差会引入选择偏差，因此同时报告成功条件下误差和全体运行结果分布；无法形成有效模型的运行标为失败，不填入任意大误差充数。

达到开发门槛的首次时间记为 T，统一预算上限为 $\tau$。对到 $\tau$ 仍未达标的运行，记录 `min(T,tau)` 和事件指示，构建开发达标曲线；最终成功仍以冻结模型的一次独立测试为准。预算结束属于行政性右删失，但安全终止和不可恢复故障可能与性能相关，必须作为竞争事件单列，不能都当作非信息性删失套用普通生存估计。建议报告截止 $\tau$ 的成功累积发生比例、各失败比例和受限运行时间分布；在适用假设得到说明时才补充生存曲线及受限平均时间。成功者达标时间的中位数仅是条件描述，不代表总体效率。

安全报告逐项列出越界提案、被监督器拒绝的执行请求、实际限位/速度/力矩违规、保护停止、失联及人工急停。分别记录事件次数、受影响运行数和物理暴露时长。事件率可写为每小时事件数，但同时保留原始分子、分母；零事件只是有限暴露下未观测到事件，不能宣称系统绝对安全。现有文档没有正式安全认证，此协议也不替代真实硬件审批。

## 7 防泄漏与公平比较

数据按训练、开发验证和最终测试三部分管理。方法可反复使用训练与开发数据，但最终测试输入或标签中超出部署可见范围的部分不向 Agent 暴露，评分反馈不参与同一版本调参。评估器在冻结模型后运行；若测试发现问题后继续改进，该结果转为开发证据，新的最终声明需要未使用的测试批次或明确标注重复使用限制。

切分单位优先采用机器人个体、采集日期、完整会话及轨迹族，避免相邻时间窗跨集合。重复采样、重叠窗口、派生文件和增强轨迹继承同一组标识。滤波器、归一化尺度、对齐参数和模型选择规则仅由训练或开发部分确定。发布清单包含数据与切分哈希、近重复检查方法和访问日志。对可能在预训练中见过公开机器人资产的基础模型，记录模型标识、日期和可知的数据来源限制，并引入新生成或未公开任务作敏感性分析；不能声称已证明不存在预训练污染。

公平基线包括原始模型、固定实验 Traditional SysID、信息驱动 Active SysID、不含 Agent 的预定义工作流、完整 Harness，以及条件允许时的人类专家。原始模型的辨识成本为零但仍接受相同测试。主因果对照固定同一后端、初始模型、参数化、参数边界、数据权限、硬件和停止规则；只替换实验选择或工作流决策模块。不同后端的最佳方法比较属于独立的系统级实验，不能混入“Agent 的收益”。

拟议消融分别去除主动实验选择、失败诊断与恢复、历史上下文检索、模型候选筛选。一次只改变目标因素，并报告被移除模块节约的计算及人工成本。安全监督和必要权限检查不作为可移除的性能消融。专家记录经验、使用工具、接触数据范围和实际工时；若专家可访问更多先验或额外仪器，则标注为非等预算参照，不把它伪装成严格公平排名。

## 8 重复实验、置信区间与预注册

任务实例、噪声种子、优化种子与 Agent 随机性分别记录。在同一实例内采用成对随机种子和相同初始状态比较方法，硬件实验采用随机或平衡顺序并记录温升、负载和会话漂移。重复次数应依据开发阶段方差与最小有意义效应做功效或精度分析，在最终测试前冻结；本文不声称某个任意次数足以证明优越性。

主要连续指标报告任务级中位数、均值或预注册稳健统计量以及 95% 置信区间。采用分层 bootstrap 时先重采任务或机器人，再重采其内部独立会话/种子；不能把强相关的毫秒采样点当成独立重复。只有一个机器人时，区间只能反映该机器人条件下的重复不确定性，不能推广为跨机器人总体区间。成对方法差值使用保持配对的重采样，公开重采样次数和随机种子。

二元成功率给出分子、分母及适当的二项区间；重复会话存在簇相关时使用簇级方法并明确有效样本限制。主要假设和指标提前指定，多重比较采用预注册的校正或明确列为探索性分析。报告效应大小与区间，不只报告显著性。样本不足、区间跨越有意义差异或失败过多时，结论应是证据不足，而不是强行选冠军。

## 9 社区证据级别与复现协议

本文沿用 Ecosystem 已规定的 L0–L3 接入级别，不重新定义等级。Bench 拟为各级别提供独立验收证据；这些协议目前尚未实现，也不表示设备安全认证。

| 既有级别 | 含义与最低证据方向 | 不允许据此推断 |
|---|---|---|
| L0 Description | 描述和装配可加载 | 已支持真机或已辨识 |
| L1 Offline | 支持标准离线数据与 Mock 辨识 | 已完成真机实验 |
| L2 Hardware | 通过声明范围内的真机实验协议 | 已达到数字孪生质量 |
| L3 Validated Twin | 有通过独立验证的模型及报告 | 对所有控制模式和工作区均有效 |

尚未验收的贡献标记 `pending`，不自动授予 L0。外部复现作为与等级并列的独立标志，记录非原作者执行者、固定资产版本、环境和报告；不新增 L4，也不以该标志改变原有等级含义。MJCF 与 USD 的验证状态分别记录。字段级检查、洁净加载和动态回放应作为对应级别的证据项，具体可执行细则有待实现与跨项目评审。

每项级别绑定具体资产版本、引擎、控制模式和日期；新固件或新转换器可能要求重新验证。贡献者是否修改 Core 作为独立兼容性字段，合法的 Core 缺陷修复需透明记录，不能为获取“不改 Core”标签而隐藏补丁。

复现包应包含任务清单、切分清单、原始资产哈希及合法获取方式、初始模型、最终补丁、运行日志、提示与工具版本、后端配置、随机种子、环境锁文件、硬件规格、评估脚本、输出表和失败记录。受限数据可提供访问申请流程与可公开的合成替代，但必须标明这只支持部分复现。闭源模型应记录服务日期和可获得的版本标识；无法固定服务行为时承认剩余漂移。

执行流程拟为：核验资产与许可 → 锁定环境 → 检查任务和切分 → 运行基线与候选 → 冻结模型产物 → 独立评分 → 重算统计 → 核对日志与安全事件 → 生成报告。当前仅 `pixi install --locked`、`pixi run --locked info` 等基础环境入口存在，尚无可以运行上述基准的命令；本稿不提供会让读者误以为已实现的虚构 CLI。

## 11 局限、伦理与有效性威胁

本协议尚未实施，因此可能包含高成本或难以自动化的检查，其区分方法优劣的能力未知。少量机器人无法代表所有机构、控制器与接触任务。真实设备的磨损、温度和采集顺序可能使配对比较失效；必须尽可能平衡顺序，并保留无法控制的混杂说明。数值仿真中的可辨识不保证真实系统中的可辨识，模型结构误差也可能被等效参数吸收。

规范化尺度、阈值和失败处理都会影响排名，因此版本变更需要公开差异并重新计算适用结果。隐藏测试可减少直接过拟合，但反复公开榜单仍可能造成群体层面的测试污染；后续需要任务轮换和版本冻结制度。社区证据分级可能偏向有硬件与计算资源的团队，故应允许合成、离线和受限数据复现分别呈现，不能将资源不足等同于质量低下。

数据发布必须遵守来源许可、保密与参与者隐私；原始真机数据、凭据和受限资产不默认进入 Git。真实运动需要独立授权和安全合同，评测预算不提供运动许可。本文没有实施真机实验，也没有收集人员数据；后续研究如涉及人工专家，须明确其知情参与、工时记录与适用伦理流程。

## 12 结论

RoboIDF-Bench 提出以分层证据评价机器人系统辨识 Agent 的研究协议。四套件分别检验真值恢复、真实泛化、实验组织和模型兼容，并通过固定合同、预算审计、独立测试及多维报告连接起来。当前可以交付的是协议文本与实验设计，不能据此声称 Agent 已提高辨识效率或达到安全要求。下一步需要将合同转化为可执行评估器，公开合法资产，完成基线及重复实验，再依据实际证据修订本文的经验性结论。
